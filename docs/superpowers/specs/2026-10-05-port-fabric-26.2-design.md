# Port WorkerMod sang Fabric 26.2 — Thiết kế

Ngày: 2026-10-05
Trạng thái: Đã duyệt (chờ review spec)

## 1. Mục tiêu

Port mod Villager Workers (hiện là Forge 1.20.1, 144 file Java / ~26k dòng) sang
**Fabric cho Minecraft 26.2**, dưới dạng **mod standalone** — không phụ thuộc
Recruits.

### Tiêu chí thành công

1. Project build xanh trên GitHub Actions (JDK 25, Loom).
2. MVP chạy end-to-end: đặt Work Area → thuê worker → worker farm/chặt cây →
   tự lấy dụng cụ từ storage → trả sản phẩm về storage.
3. Cấu trúc package, modid, lang key, asset path giữ nguyên bản Forge để dễ
   đối chiếu và port tiếp các worker còn lại.

## 3. Ánh xạ Forge → Fabric

| Forge / Recruits | Fabric 26.2 |
|---|---|
| `DeferredRegister` | `Registry.register()` trong `onInitialize()` |
| `SimpleChannel` + corelib `Message` | Fabric Networking API (payload + codec) |
| `ForgeConfigSpec` | JSON config (`config/workers.json`, Gson) |
| corelib `ScreenBase` | `AbstractContainerScreen` (vanilla) |
| corelib `ContainerBase` | `AbstractContainerMenu` (vanilla) |
| `RecruitsCheckBox`, `BlackShowingTextField`, `DropDownMenu`... | Widget tự viết từ `AbstractWidget` / `EditBox` / vanilla `Checkbox` |
| `RecruitsHireTrade` + registry | Spawn egg → right-click hire bằng emerald |
| `AbstractChunkLoaderEntity` | `PathfinderMob` |
| Recruits `AsyncPathNavigation` | vanilla `GroundPathNavigation` |
| `ResourceLocation` | `Identifier` |
| `EntityRenderer#render` | `EntityRenderer<T, S>` + `createRenderState` / `extractRenderState` / `submit` (render-state system từ 1.21.9) |
| `@Mod` + event bus | `ModInitializer` / `ClientModInitializer` |
| Mixin (Forge mixin loader) | Mixin (native trong Fabric) |

### Hành vi phải tự implement lại (Recruits cung cấp)

| Hành vi | Thiết kế thay thế |
|---|---|
| owner (UUID + name) | Field NBT-persisted, synced |
| hire / disband | Right-click với emerald theo `cost` config |
| inventory | `SimpleContainer` 9 slot (giữ index 8 làm food slot như bản gốc) |
| morale | Field + tick hàng ngày (không home −10, có home +5) |
| followState | Enum đơn giản (`IDLE`, `WORK`, `FOLLOW`, `MOVE_TO`) |
| needsToSleep / shouldWork | Field + kiểm tra theo thời gian trong ngày |
| upkeep (lương/thức ăn) | Port `RecruitStorageUpkeepGoal` thành goal độc lập |
| team | Bỏ — chỉ owner + `teamAccess` flag trên work area |

### Cấu trúc nguồn (split environment source sets)

Theo template: `src/main/java` (common) và `src/client/java` (client-only).
Code client hiện tại nằm trong `client/` package — chuyển sang source set
`client` để tránh load class client trên server.

## 5. Thiết kế component

### 5.1 AbstractWorkerEntity

- Extends `PathfinderMob`, implements interface `IOwnable` (tự định nghĩa).
- State: `ownerUUID`, `ownerName`, `morale`, `followState`, `neededItems:
  List<NeededItem>`, `farmedItems`, `forcedDeposit`, `lastStorage`, `isFleeing`,
  `homeAreaUUID`.
- Abstract: `getCurrentWorkArea()`, `setCurrentWorkArea()`, `shouldWork()`,
  `getWorkGoal()`.
- `registerGoals()`: các goal chung (deposit/get items, go home, flee) +
  `WorkerOpenDoorGoal`.
- `mobInteract()`: owner right-click mở GUI; non-owner right-click với emerald
  → hire (trừ tiền theo config).
- Pickup filter: `wantsToPickUp` theo config list (`*Pickup`) + `wantsToKeep`.

### 5.2 Work Area system

- `AbstractWorkAreaEntity extends Entity` — vô hình, no-gravity, invulnerable.
  Giữ AABB vùng, owner, facing, width/depth/height, teamAccess. Toàn bộ state
  sync qua `EntityDataAccessor`.
- `createArea()` tính AABB theo facing + kích thước. `isAreaOverlapping()`
  chặn overlap (trừ BuildArea). `canWorkHere(worker)` = cùng owner hoặc
  (teamAccess + cùng team).
- `IPermissionArea` (owner, teamAccess, teamStringID) gate right-click container.
- Mỗi area giữ **Stack công việc** (scan trước, pop sau): CropArea 5 stack
  (plant/break/plow/boneMeal/pick), LumberArea `Stack<Tree>` + plant/boneMeal.
- `StorageArea`: `Map<BlockPos, Container>` + `StorageType` enum + scan chest
  trong AABB.
- GUI mở qua message server→client (`MessageToClientOpenWorkAreaScreen`).

### 5.3 AI Goals

Vòng lặp chung mỗi `*WorkGoal` (giữ nguyên state machine của bản gốc):

```
SELECT_WORK_AREA → MOVE_TO_WORK_AREA → PREPARE_* (scan, kiểm tra tool,
add NeededItem nếu thiếu) → làm việc (pop stack) → DONE / ERROR
```

- `canUse()`: `!needsToSleep() && shouldWork() && !needsToGetToChest() && area
  còn tồn tại`.
- Cooldown ngẫu nhiên ~300 tick trước khi chọn area mới.
- `AbstractChestGoal`: base cho storage interaction — scan `StorageArea` trong
  64 block, ưu tiên `lastStorage`, loại trừ `visited`, sort theo distance.
  `interactChest` mở/đóng chest có animation + sound.
- `GetNeededItemsFromStorage`: state machine — pre-scan chest chứa item cần,
  đi thẳng tới đó, extract theo `NeededItem.matches`.
- `DepositItemsToStorage`: mirror — bỏ qua armor + `wantsToKeep`, fill stack
  khớp trước rồi mới empty slot.
- `NeededItem`: `Predicate<ItemStack>` + count + required + sourceKey; merge
  theo `getMatchKey`.

### 5.4 Network

Nhóm payload (Fabric API, thay corelib `Message`):

- **WorkArea CRUD** (client→server): `AddWorkArea`, `UpdateWorkArea`,
  `RotateWorkArea`, `UpdateOwner`, mỗi loại area có `Update<Area>` riêng.
- **Server→client**: `OpenWorkAreaScreen`.
- **Config sync**: `UpdateConfig` (gửi khi player join).
- **Merchant/Courier** (post-MVP).

Cơ chế: client GUI gửi update → server tìm entity theo UUID trong bán kính →
mutate → `EntityDataAccessor` tự sync xuống client.

### 5.5 Config

JSON tại `config/workers.json` (FabricLoader config dir), Gson. Giữ nguyên
các nhóm của bản gốc:

- Hire cost (Farmer 10, Lumberjack 12, Miner 16, Builder 20, Merchant 30,
  Courier 20, Cook 25)
- Villager breeding (post-MVP)
- Claim gating: `ShouldWorkAreaOnlyBeInFactionClaim`,
  `ShouldOnlyPlacingBuildingsBePossible` (giữ flag, MVP chỉ enforce
  `ShouldOnlyPlacingBuildingsBePossible` khi không có claim)
- BuildMode enum (`FREE`, `PRESET`, `PRESET_FACTIONS`) — post-MVP dùng
- AnimalPenMaxAnimals, pickup/ignore lists, WorkersReplaceAllay (post-MVP)

Ghi file với comment mô tả default. Load một lần khi server start; không cần
hot-reload (bản gốc cũng yêu cầu restart).

### 5.6 GUI (MVP)

- `WorkAreaScreen` — base: nút move (F/B/L/R, shift = 5 block), rotate,
  destroy, text field tên, checkbox teamAccess, nút chọn owner.
- `CropAreaScreen`, `LumberAreaScreen`, `StorageAreaScreen`.
- Widget dùng vanilla (`Button`, `EditBox`, `Checkbox`); widget tùy biến
  (dropdown, scroll) để post-MVP.

### 5.7 Rendering

- Render-state system mới (1.21.9+): `EntityRenderer<T, S>` với
  `createRenderState` / `extractRenderState` / `submit`.
- `WorkerAreaRenderer`: vẽ box AABB + item icon xoay; box xanh cho area kế
  cận cùng team.
- Worker renderer: theo `RecruitsClientConfig.RecruitsLookLikeVillagers` trong
  bản gốc — thay bằng config riêng `LookLikeVillagers` (default true). MVP có
  thể chỉ cần một kiểu renderer hoạt động, kiểu còn lại thêm sau.
- `StructurePreviewWidget` (3D preview) — post-MVP.

### 5.8 Mixin

`MixinVillager` (breeding theo saturation) — port sau MVP. Hạ tầng mixin
(`worker-mod.mixins.json`) setup sẵn từ template ở bước 0.

## 6. Phạm vi MVP & chia bước

Mỗi bước phải **build xanh trên CI** mới sang bước sau.

| Bước | Nội dung | Verify |
|---|---|---|
| 0 | Branch `fabric-26.2`, cấu trúc Loom từ template, workflow GH Actions, push | CI xanh với project rỗng |
| 1 | Mod init + registry + `AbstractWorkerEntity` base + config JSON + spawn egg + renderer tối thiểu | CI xanh; spawn được worker trống (verify qua `runServer` log) |
| 2 | `AbstractWorkAreaEntity` + `CropArea` + `LumberArea` + `WorkAreaScreen` + network + `WorkerAreaRenderer` | CI xanh; đặt/điều khiển area, thấy box |
| 3 | `FarmerWorkGoal` + `LumberjackWorkGoal` + `StorageArea` + `AbstractChestGoal` + get/deposit | CI xanh; **MVP end-to-end** |

**Ngoài MVP** (port ở các iteration sau, mỗi worker/thệ thống một đợt):
Miner, Builder, Courier, Cook, AnimalFarmer, Fisherman, Merchant; preset
system + StructurePreviewWidget; villager invite; allay replacement; breeding
mixin; merchant trade GUI.

## 7. Chiến lược verify

- **Build**: mỗi push lên branch → GH Actions → `gh run watch` →
  `gh run view --log-failed` khi đỏ.
- **Chạy thử**: `./gradlew runServer` trên CI (headless) với script khởi động
  ngắn để xác nhận mod load không crash, log sạch.
- **Logic**: với các phần khó verify qua CI (AI state machine, work area
  math), viết self-check `assert` chạy được bằng `runServer` hoặc test thuần
  Java cho phần không phụ thuộc Minecraft.
- **Đối chiếu hành vi**: so với bản Forge từng hàm khi port (diff logic), giữ
  nguyên hằng số và thứ tự state.
